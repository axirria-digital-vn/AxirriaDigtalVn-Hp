Perito for Jira – Documentation

Last updated: [[ngày đưa lên web]]

Perito writes test cases for a Jira issue using the issues around it as context. It asks your team about unclear requirements before guessing, suggests tests for areas a change may affect, and warns you about tests you may already have.

1. Install

  1. Open Perito for Jira on the Atlassian Marketplace and select "Get it now".
  2. Choose your Jira Cloud site. A site admin approves the permissions listed below.
  3. Open any Jira issue. The Perito panel appears on the issue [[đúng vị trí/tên panel trong UI]].

Perito is free for teams of up to 10 users.

Perito sends issue text to OpenRouter (openrouter.ai) to generate test cases. No other external hosts are contacted [[Duy xác nhận danh sách egress]].

3. Generate test cases

  1. Open a Jira issue and select [[tên nút, ví dụ "Generate tests"]] in the Perito panel.
  2. Perito collects context: linked issues, issues in the same epic or parent, and issues that share business keywords, including bugs.
  3. Perito writes [[6–10]] test cases. Each test case has steps, test data and an expected result.
  4. Review each test case: keep it, edit it or drop it. When you drop a test, you can give a short reason.

4. Clarifying questions

If a requirement is unclear, Perito posts one comment on the issue titled "[Perito] Questions before writing tests", with numbered questions (Q1, Q2…).

  • Answer in a normal Jira comment, for example "Q1: Not applied to sale items." Your BA does not need to open Perito.
  • Test cases that depend on an unanswered question stay in Draft and show "Waiting for answer: Q2".
  • When an answer arrives, Perito rewrites the related draft tests. If the trigger misses an answer, select [[tên nút "Read answers again"]].
  • To use draft tests without waiting, select [[tên nút "Use now"]]. These tests keep the label "not clarified".
  • If an answer differs from the issue description, Perito follows the answer and shows a warning so the issue can be updated.

5. Impact tests

Besides tests for the issue itself, Perito suggests 1–3 tests for each area the change may affect (up to 5 areas). Each impact test shows where it came from:

  • 🔗 a linked issue (including bugs; for a bug, the test repeats the steps that caused it under the new conditions)
  • 📝 the "Affected areas" section of the issue
  • 💬 your team's answer to the affected-areas question
  • 🤖 an AI suggestion, used only when the sources above give nothing. These tests show the quoted text from both issues and should be checked before use.

Tip: add an "Affected areas" section to your issues. Perito then uses it directly and does not need to ask.

6. Possible duplicates

Perito compares new test cases with existing tests of the issue and of the related issues it used.

  • Possible duplicate: grouped under "Possible duplicates" and dropped by default. Open the group to compare with the existing test and decide.
  • Adds to an existing test: shown under "Adds to existing tests", with what is new.

Perito never changes your existing tests.

8. Data and privacy

  • Does data leave Atlassian? Yes. Issue text needed for test generation is sent to OpenRouter and an AI model provider with zero data retention.
  • Is my data used to train AI models? No.
  • Where is data stored? [[Forge Storage / Forge SQL]] within your Atlassian site.

Details: Privacy Policy and Data Processing Addendum.

9. Uninstall

A site admin can uninstall Perito from Jira settings → Apps → Manage apps. Data stored by Perito is deleted according to Atlassian Forge data deletion rules. Comments and test cases that Perito wrote to Jira stay until you delete them.
